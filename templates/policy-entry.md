# 策略条目模板

> 四要素缺一不可。缺任何一项 = 这条策略不会被加载。
> 依据 survey：技能是结构化包（触发条件 / 执行策略 / 终止条件 / 复用接口），不是一段 prompt。

```markdown
## P-00X <一句话策略名>  v<版本号>
- 触发条件：<什么场景下生效，尽量可判定>
- 执行策略：<具体动作序列，越可执行越好>
- 终止条件：<什么情况下结束 / 不再执行>
- 复用接口：<哪些任务类型通用；是否可与其他策略组合>
- 版本：v<n>（v<n-1> 失效原因：<为什么上一版没拦住>）
- 证据：<关联 recurrence-report-YYYY-MM-DD.md>
- 效果验证：事故数 <前> → <后>（连续 2 期为 0 则转 COLD）
```

## 演进三条路径

| 路径 | 含义 | 何时用 |
|---|---|---|
| **FIX** | 就地修补失效条目 | 同一策略被违反，但方向没错 |
| **DERIVED** | 从父策略派生专精变体 | 某类子场景需要更细的规则 |
| **CAPTURED** | 从一次成功执行抽取全新策略 | 出现了一类从没遇到过的好做法 |

## 改动纪律

- **diff 级最小改动**，禁止整段重写（可回滚 + 可 review）
- 版本用 DAG 记谱系（哪个策略派生自哪个）
- **安全类（凭据 / 权限 / 删除 / 外发）永不自动改**，必须人工批准

## 反例（不许这样写）

```
## 记得检查数据
- 要仔细一点，别再漏了
```
❌ 无触发条件、无终止条件、无复用接口、执行策略不可执行、无法验证 —— 这不是策略，是许愿。

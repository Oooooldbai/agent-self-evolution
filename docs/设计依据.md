# 设计依据

> 每个设计决策都要有出处。本文记录：外部证据 → 我们的实证 → 设计取舍。

## 一、外部证据

### 1. Rutgers & UNC Charlotte survey（19 种技能进化方法 + 10 个评估基准）

**四个进化范式**（按信号来源 + 粒度）：

| 范式 | 信号来源 | 粒度 | 代表 |
|---|---|---|---|
| 执行反馈 | 单次运行的错误输出、运行时异常 | 步骤级 | SkillForge、CoEvoSkills、Skills-Coach、Ctx2Skill、AutoSkill、SkillClaw、EmbodiSkill |
| 轨迹蒸馏 | 多次运行的成功/失败轨迹 | 序列级 | SPARK、Trace2Skill、Memento-Skills、XSkill |
| 压缩与增强 | 技能库整体结构（重叠/冲突/空白） | 库级 | SkillNet、SkillX、SkillReducer、SkillFoundry |
| 强化学习 | 任务完成奖励 | 任务级 | D2Skill、SkillRL、SkillOS、Skill1 |

**采纳的三条结论**：
- **诊断与改写分离**：SkillForge / CoEvoSkills 先用验证器做根因分析再改写，效果显著优于
  AutoSkill / SkillClaw 那种"直接在原始轨迹上让模型自己改"。后者会把任务特异性的
  **偶然行为**当成可复用模式。 → 本包 `--attr` 只出诊断，不改文件。
- **纵向追踪是行业盲区**：没有任何 benchmark 追踪技能在多轮反馈后是否真正变好。
  → 本包 `--trend` 做期际对比。
- **安全只做一次性检查不够**：不受控的技能自进化可能悄悄剥离已有安全约束。
  → 安全类策略硬编码人工批准。

**未采纳**：RL 路线（依赖任务级奖励，且分不清是技能进化了还是模型本身变强了）。

### 2. Agent 自进化五层（Memory / Policy / Skill / Tool / Model）

- Reflection 解决**这一次**，Evolution 解决**下一次**
- 判断标准不是"一次做多好"，而是**做完 1000 次后有没有比第一次强**
- 多数 self-improving 方案停在 **L1 记忆**，本包目标 **L2 策略**

### 3. Darwin Skill 的策略演进三条路径

FIX（就地修补）/ DERIVED（派生专精变体）/ CAPTURED（从成功执行抽取新策略）；
diff 级最小改动、可回滚、版本 DAG 记谱系。 → 已写入策略模板。

### 4. 技能的结构化定义

技能 ≠ prompt，≠ API 调用。它是结构化包：
**触发条件 / 执行策略 / 终止条件 / 复用接口**。 → 策略条目四要素的来源。

### 5. Claude Code L4 Auto Dream + OpenClaw Dreaming（对照卡挂账规格 · 2026-10-15 老白点火）

- **规格真源**：LSB 对照卡《ClaudeCode五条价值观与记忆系统-对照我们的实现》§L4——
  独立后台子代理、**24 小时 + ≥5 个新会话**触发、五项动作（合并重复记忆 / 删除无效条目 /
  提炼核心模式 / 优化索引 / 生成跨会话高级洞察），模拟人脑睡眠记忆巩固。
- **晋升门槛（OpenClaw Dreaming）**：**召回次数 / 查询多样性 / 来源可信度**三重筛选——
  记忆不无条件晋升，三关都过才配进常驻层。
- **旧版差距**（对照卡已判 🔴 最大缺口）：v0.3.x 把触发交给 cron 每日裸跑
  （无 24h+5 会话双条件）、无三重门槛——「cron 每天跑」不等于 Auto Dream。
  v0.4.0 补齐两项；**"只出报告不自动改"红线不动**。

## 二、我们的实证（本项目起源环境 · 2026-10-12）

| 现象 | 数据 |
|---|---|
| 红线一天内被违反 | **4 次**（09:15 / 14:09 / 16:17 / 17:28），条款早已写进 SOP |
| 文档型失效 | 某类：**条款 8 条 / 事故 6 次** |
| 机制假绿 | feedback 解析器漏读 → 「待复盘 0」假绿，25 条积压躺三个月 |
| 凭据明文事故 | 7 天内 2 次 |
| 记忆膨胀 | MEMORY.md 达 25KB / 274 行，而自检标准写的是「超 2KB 就蒸馏」→ 从未触发 |

**由此得出的元结论**：

> 条款写在文档里，靠"下次记得读" → 已被实证无效。
> 标准不落到断言里 = 没有标准。

## 三、设计取舍

| 决策 | 选择 | 理由 |
|---|---|---|
| 归因后是否自动改 | **不自动改** | survey 结论：诊断与改写分离效果更好；且自动改有安全风险 |
| 统计口径 | 事故 / 条款分开 | 只数问题会自我膨胀；分开后能自动识别"文档型失效" |
| 置信度阈值 | <0.5 不改 | 防止把噪声当模式 |
| 安全类策略 | 永不自动改 | survey 盲区三 |
| 是否用 RL | 不用 | 成本高，且分不清技能进化 vs 模型变强 |
| LLM 缺失时 | **显式降级**，不静默跳过 | 静默假阴性是我们自己的事故之一（infer 三坑） |
| Auto Dream 触发 | **24h + ≥5 新会话双条件**，后台每小时探测、闸门自判 | 对照卡 §L4 挂账规格；单靠 cron 每日跑 = 无条件裸跑，已判定不算 Auto Dream |
| 闸未到点怎么表现 | `exit 3`（信号源错 `exit 2`），打印数字，**不写状态** | 我们自己的假绿实证："已配置 ≠ 已运行"；没跑成就不许消耗触发机会 |
| 三重门槛信号源 | recall-log 权威 + 会话日志近似兜底，**皆无则显式降级** | 召回信号现成为零，但 0 ≠ "没人用"，不许拿无信号当结论 |
| 门槛后是否自动晋升/删除 | **否，仍只出报告** | 诊断与改写分离 + 自动删记忆不可逆 |
| L2 记忆怎么建 | **自建**（不走插件，2026-10-16 老白拍板） | 插件多为自有格式，与已投入资产（auto_dream / recall-log / gate 断言）不兼容；自建 100% 贴 L2 规格（索引硬限 200 行 25KB / 四类 / 只记实时读不到的） |
| L2 的自动化边界 | 机械层自动（切片 / 报告 / 召回记录），**语义层永远人工裁定** | 自动写记忆不可逆且会污染真源；"靠记得写"已被实证无效 → 只把"素材出现"变机械 |
